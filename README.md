# RoboSim

**RoboSim** — проект системы автоматизированной проверки решений задач школьной робототехники в физической симуляции. Предполагаемый сценарий применения — выполнение программ участников в воспроизводимой виртуальной среде с ограниченными вычислительными ресурсами и последующей интеграцией с Яндекс.Контест.

В текущем состоянии репозиторий содержит **исследование по выбору физического симулятора**, а не готовую систему проверки решений. Для дальнейшей разработки из трёх кандидатов — PyBullet, MuJoCo и Gazebo Jetty — отобраны **MuJoCo и PyBullet**. Решение основано на сравнении производительности шести стандартных физических сцен при одинаковых ограничениях Docker.

## Результаты исследования

Выполнено 180 запусков: 3 симулятора × 2 сценария × 3 уровня нагрузки × 10 повторов. Все запуски прошли предусмотренные проверки корректности.

| Место | Симулятор | Относительная производительность | Медианная пиковая память |
|---:|---|---:|---:|
| 1 | **MuJoCo** | **1,0000** | **35,5 MiB** |
| 2 | **PyBullet** | **0,5998** | **56,3 MiB** |
| 3 | Gazebo Jetty | 0,0934 | 43,2 MiB |

Показатель производительности — геометрическое среднее нормированных медианных скоростей по шести нагрузкам. За единицу в каждой нагрузке принимается максимальная скорость среди трёх симуляторов. Значения памяти — медианы пикового потребления в соответствующих контейнерах.

Полные таблицы измерений, критерии допуска и правила ранжирования приведены в [отчёте](docs/SELECTION_RESULTS.md). Исходные записи доступны в [`data/selection/main.jsonl`](data/selection/main.jsonl); методика описана в [протоколе исследования](docs/RESEARCH_PROTOCOL.md).

## Методика

Бенчмарк сравнивает стоимость вычисления физики твёрдых тел без графического интерфейса, датчиков и алгоритмов управления.

| Параметр | Значение |
|---|---|
| Симуляторы | PyBullet 3.2.7, MuJoCo 3.16.0, Gazebo Jetty (`gz-sim 10`) |
| Сценарии | `rest` — тела установлены на полу; `drop` — тела изначально расположены над полом |
| Число тел | 1, 8, 32 |
| Геометрия тела | Параллелепипед 0,30 × 0,24 × 0,12 м |
| Масса тела | 2 кг |
| Гравитация | 9,81 м/с² |
| Физический шаг | 0,01 с |
| Прогрев / измерение | 100 / 2000 шагов |
| Повторы | 3 в пилотной серии, 10 в основной |
| Ограничения контейнера | 2 CPU (`cpuset 2-3`), 2 GiB RAM, без дополнительного swap, сети и GUI |

Каждый запуск выполняется в отдельном контейнере. Порядок сценариев перемешивается воспроизводимым образом, порядок симуляторов чередуется. Фиксируются длительность физических вычислений, скорость моделирования в шагах/с, CPU-время, пиковая память, соблюдение ограничений и успешность проверки конечных состояний.

Правило выбора задано в [`docs/RESEARCH_PROTOCOL.md`](docs/RESEARCH_PROTOCOL.md) и одинаково применяется ко всем симуляторам.

## Структура репозитория

```text
.
├── benchmark/
│   ├── docker/             # Docker-образы для Python-движков и Gazebo
│   ├── spec.py             # Параметры и размещение физических тел
│   ├── profile.json        # Ресурсные ограничения и число повторов
│   ├── make_worlds.py      # Генерация SDF-сцен для Gazebo
│   ├── python_engine.py    # Исполнитель PyBullet и MuJoCo
│   ├── gazebo_runner.cpp   # Исполнитель Gazebo
│   ├── CMakeLists.txt       # Сборка исполнителя Gazebo
│   ├── run.py               # Оркестрация запусков в Docker
│   ├── report.py            # Обработка измерений и формирование отчёта
│   └── test_protocol.py    # Тесты протокола и оценки результатов
├── data/selection/
│   ├── pilot.jsonl         # Пилотные измерения
│   └── main.jsonl          # Основные измерения
├── docs/
│   ├── RESEARCH_PROTOCOL.md
│   └── SELECTION_RESULTS.md
├── src/robo_sim/robots/models/
│   └── benchmark_robot.urdf
├── pyproject.toml
└── uv.lock
```

Каталог `benchmark/worlds/` создаётся генератором сцен и не хранится в Git. URDF-модель сохранена как исходный ресурс для следующих этапов RoboSim; в текущем микро-бенчмарке используются упрощённые тела с соответствующими габаритами, **не полный робот**.

## Требования

- Linux x86-64 с Docker Engine и поддержкой cgroups v2.
- Доступ к логическим процессорам `2-3`, указанным в [`benchmark/profile.json`](benchmark/profile.json). На другой машине привязку процессоров необходимо настроить отдельно и зафиксировать изменение условий.
- Python 3 для управляющих скриптов и модульных тестов (используется стандартная библиотека).
- Доступ к Docker Hub и репозиторию пакетов Gazebo при первой сборке образов.

PyBullet и MuJoCo устанавливаются **внутрь контейнера** на Python 3.11; Gazebo Jetty собирается в образе на базе Ubuntu 26.04. Локальная установка трёх симуляторов для выполнения бенчмарка не требуется.

## Воспроизведение

Команды выполняются из корня репозитория.

### Проверка протокола и подготовка сцен

```bash
PYTHONPATH=benchmark python -m unittest discover -s benchmark -p 'test_*.py' -v
python benchmark/make_worlds.py
```

### Сборка Docker-образов

```bash
docker build -f benchmark/docker/python/Dockerfile -t robosim-selection-python:v1 benchmark
docker build -f benchmark/docker/gazebo/Dockerfile -t robosim-selection-gazebo:v1 benchmark
```

### Пилотная серия

```bash
python benchmark/run.py --pilot --output data/selection/pilot-reproduction.jsonl
python benchmark/report.py data/selection/pilot-reproduction.jsonl --output docs/SELECTION_PILOT_REPRODUCTION.md
```

Пилот состоит из 54 запусков и проверяет работоспособность стенда; по нему окончательный выбор не производится.

### Основная серия

```bash
python benchmark/run.py --main --output data/selection/main-reproduction.jsonl
python benchmark/report.py data/selection/main-reproduction.jsonl --output docs/SELECTION_REPRODUCTION.md
```

Основная серия состоит из 180 запусков. Отчёт формируется только на основе измерений, записанных в указанный JSONL-файл. Для повторного построения опубликованного отчёта без новых вычислений:

```bash
python benchmark/report.py data/selection/main.jsonl --output docs/SELECTION_RESULTS.md
```

Для повторного запуска используются отдельные имена файлов, чтобы не перезаписывать опубликованные исходные данные. Точные версии библиотек и идентификаторы собранных образов регистрируются в результатах запусков.

## Область применимости результатов

Исследование оценивает **вычислительную стоимость конкретных физических микронагрузок**. Оно не устанавливает сравнительную точность симуляторов, качество моделирования датчиков, эффективность управления роботом или пригодность всей системы к проверке олимпиадных решений.

Особенность сценария `drop`: 100 шагов прогрева выполняются до начала измеряемой части. Поэтому само падение и первоначальный удар могут происходить во время прогрева; результаты `drop` нельзя интерпретировать как отдельное сравнение производительности обработки ударных контактов.

Ограничения Docker обеспечивают одинаковые квоты, но не исключают влияние других процессов на общем оборудовании. Конфигурация хоста, образы и версии пакетов имеют значение для воспроизведения абсолютных значений времени.

Выбранные по результатам данного этапа MuJoCo и PyBullet предназначены для последующей реализации модели робота, задач, датчиков и механизма автоматической проверки. Эти компоненты не входят в текущую версию репозитория.
